# 2026-10-10: UX rework from the design review

This log covers implementing the findings in
[`2026-10-10-ux-review.html`](2026-10-10-ux-review.html). The rules that came out of
that review, written so future agents don't repeat the same mistakes, are in
[`AGENT_UX_GUIDELINES.md`](AGENT_UX_GUIDELINES.md).

## Goal

The app exists to help a Sleeper manager **acquire and position players based
on celestial standings**. The review found that the celestial numbers almost
never reached a decision: there were seven tabs, four competing "scores", and
no screen that said "do this". The rework makes every screen end in a move,
and gives the stars a single, explicit dial for how much they count.

## The model: Stats, Stars, Oracle

The new module `core/lib/oracle.ts` defines three numbers, and every screen uses them:

| Number | Meaning | Source |
| --- | --- | --- |
| **Stats** | This week's projected points (league scoring) | Sleeper projection |
| **Stars** | This week's celestial favorability, 0–100 | `computeWeeklyPlayerFavorability` with `isStarter: true` |
| **Oracle** | `(1 − λ) × Stats + λ × Stars`, where Stats is normalized so 25 pts = 100 | Both, weighted by the user's λ |

λ is set in one place: the **Oracle** chip in the header, which opens a
slide-over panel with a slider, four presets (Stats only / Mostly stats /
Mostly stars / Stars only), and a live preview of what changes at that
setting. It replaces the λ slider in Settings and the separate "Scoring
Model" tab. The detailed star weights are still there, under a disclosure in
that panel.

One tone scale (`favorabilityTone`: ≥84 / 75–83 / 65–74 / <65) colors every
Stars value, and the Matchup explainer legend uses the same thresholds.

## Information architecture

Seven tabs became four (old tab ids still resolve via `TAB_ALIASES`):

| Tab | Answers | Contents |
| --- | --- | --- |
| **This Week** | Who do I start? | Ranked moves (lineup swaps, top waiver, bye plan, trade idea), matchup card, ideal roster, bye outlook; full matchup details below |
| **Waivers** | Who do I add or drop? | Need-aware waiver moves, then the player directory (Stats / Stars / Oracle table, paginated) |
| **Trades** | Who do I trade with? | Partners ranked by mutual lineup fit: who you give, who you get, and why |
| **League** | Where do I stand? | Standings, then any team's roster in lineup order |

Header: a single sync indicator (pulses only while syncing), the Oracle chip,
and the user's avatar opening Settings. On desktop the bottom nav is hidden. On
phones it is the only nav. Mock mode shows a "Back to {user} →" banner, and
debug IDs moved into Settings.

## Recommendation logic

- **Lineup check** (`computeLineupCheck`): fills the most restrictive slots
  first (QB, then TE, …, then FLEX, then SUPER_FLEX) using Oracle score. It
  reports each swap with Stats and Stars side by side. When the two disagree,
  it reports the λ at which the decision flips.
- **Waivers** (`computeWaiverMoves`): never suggests dropping a starter, a
  player whose only problem is a bye this week, or a player needed for minimum
  positional depth (dedicated slots + 1; QB = 3 in superflex). It never
  suggests adding someone who is Out, IR, PUP, suspended or not active. Moves
  that would start come first; results are ranked *before* the limit is
  applied, so "top waiver move" is the same on every screen. Injury codes are
  written out ("not active", "on injured reserve").
- **Trades** (`computeTradePartners`): looks for a 1-for-1 where your bench
  player would start for them and their bench player would start for you.
  Partners are ranked by combined gain. A simple count of surplus vs. need
  found no partners in this league, so this replaced it.
- **Byes** (`computeByeOutlook`): only remaining regular-season weeks, starters
  first.
- The app is read-only by design: recommendations name the players, slot and
  reason, and there are no buttons or links that act on Sleeper. The review
  mock-ups proposed "Set lineup in Sleeper" style buttons; they were built and
  then removed at the owner's request.

## Data fixes found during QA

- **Starters come from the current week's matchup.** Sleeper's `/rosters`
  `starters` lagged behind the week-5 matchup lineup. For example, it still
  listed a player the manager had already benched. `teamStarters` and celestial
  team metrics now come from the current-week matchup, with `/rosters` as a
  fallback.
- **Team elements and stacks are derived, not constants.** `teamComparison`
  elements come from `dominantElements` over the actual starters, and
  conjunctions come from real same-team stacks (`teamStacks`). Hard-coded
  catalysts and risks were removed. The legacy mock path shows "—" instead of
  fake text.

## Smaller review items addressed

- Removed: the TelemetryBar, the leaderboard and competitor rosters on This
  Week (they're on League), the duplicate start/sit row on the matchup card, the
  `<0.1ms` badge, Cloud Run egress text, "Opp: vs", and the Path of Ascension
  outside drafts.
- Renamed: the toggle "Include players without an NFL team", board sort
  "Free agents only", and the board status column (Free agent / Yours / Rostered).
- Board: full names, team · bye, sticky header, 25 rows per page with "Show N
  more", and Oracle as the default sort.
- Player modal: Oracle (λ) and Stars replace DraftScore and Wk Fav. Role
  comparison is written in Oracle terms.
- Standings: slot labels are hidden once teams have records. The red/green
  "verdict" chip became a quiet Spirit bar.
- Matchup: the long explainer is now a "How Stars this week is scored"
  disclosure with the real formula and tone legend.
- Each screen keeps its mystical name as an eyebrow ("Alchemical
  Transmutations") above a plain title ("Waivers").

## Follow-up: matchup telemetry showed identical numbers

The owner reported the matchup card reading "73.6% vs 73.6%" and "90.0 vs
90.0". Findings and fixes:

- **Astral Favorability was mislabeled and one-sided.** It was the season-long
  average Spirit of the *whole roster* (bench included), labeled "Transit
  Alignment". It is now the mean of this week's Stars across each side's
  starters, matching its new subtitle "Avg starter Stars · this week".
  `OneiromancyContext` also overwrote only the user's side with roster
  Spirit after sync, so the two sides came from different formulas; that
  override is removed. Real values this week: 72.11 vs 72.14, checked
  against the per-player Stars in the same view.
- **Squad Harmony 90 vs 90 is correct.** The score is a step function: 50
  base, +12/+18 trine, +9/+18 per QB stack (cap 30), and +10 for all four
  elements. Both lineups hit +12, one stack (Winston–Fields NYG,
  Goff–J. Williams DET), and +10. The card now lists these bonuses under each
  score (`computeRosterHarmonyBreakdown`), shown only when they add up to the
  displayed score.
- Ties read "even" instead of "vs", the "%" sign is gone (Stars are 0–100
  points), and the summary line now attributes "favored" to win probability
  instead of claiming an astral edge.

## Follow-up: stars must weigh in on every player value

The owner flagged Trades and League valuing players by projected points
alone. Fixed:

- **Trades** (`computeTradePartners` now takes λ): "would start" and gains
  use Oracle, not projections. Every give/get box and the partner's roster
  list show Oracle, points and Stars (`describeValue`, `ValueLine`), and
  gains read "+X Oracle".
- **League**: roster rows lead with Oracle, then points and Stars, under a
  column header; the bench sorts by Oracle.
- **Waivers**: the card headline is the Oracle gain, with points and Stars in
  parentheses (it was "+9.3 pts/wk").
- **This Week**: the matchup card shows each side's average starter Stars
  under its projected score.
- Guideline 10 now forbids presenting projections alone as a player's value,
  and the definition of done checks for it.

## Follow-up: League defaulted to Sleeper standings (owner correction)

The owner: "When I go to the league page, it defaults to standings. I CAN
ALREADY SEE THIS INFORMATION ON THE SLEEPER APP. ... This apps job is to tell
me an overall players advantage based on the scoring metrics WE set. Stop
defaulting to what you think is best and stick to my mission."

The earlier IA choice ("standings first") was the agent's own judgment and
was wrong. Fixed:

- **League now opens on Oracle rankings** (`computeTeamOracles`): every
  team's current starting lineup rated by mean Oracle at the owner's λ and
  star weights, with Stars, projected points, the gap to the owner's lineup
  ("+2.3 over you"), and each lineup's strongest and weakest starter. It can
  be re-ranked by Stars or projected points. The win-loss record is a small
  muted note; the Sleeper standings view is gone. Selecting a team opens its
  lineup breakdown (by Oracle) below. An "Adjust the Oracle" link opens the
  panel.
- **The This Week matchup card leads with each lineup's Oracle**; Stars and
  projected points are secondary.
- The mission is now quoted at the top of `AGENT_UX_GUIDELINES.md`, which
  forbids defaulting any view to data Sleeper already shows and requires
  checking that λ and star weights actually move what a screen shows.
- Test 8.4.6 now asserts League leads with "Oracle rankings" and not
  "Standings".
- **The star weights were decoration, and now they work.** In the browser,
  setting Celestial Transits from 30 to 0 changed nothing anywhere.
  `recomputeDraftScores` reused each player's stored Spirit and never
  reapplied the weights. It now recomputes Spirit from the divination
  breakdown with the owner's weights (identical numbers at the default
  weights). `recomputeDraftState` also refreshes the matchup's team Stars.
  Verified in the browser: the same change now moves every rating (e.g.
  BakchodLaunde 72.6 → 71.7) and reorders the league.
- **λ and the star weights now persist** (localStorage `oneiromancy_oracle`).
  Before, a reload silently reset the owner's model to the defaults.
  Verified that they survive both the background sync and a reload.
- "Adjust the Oracle" on League opens the panel in place. The old `dial` tab
  alias sent the user back to This Week.

## Follow-up: default λ is 0.75 (owner's call)

The owner asked whether the default Oracle settings had been changed. They
had not: `DEFAULT_CHAOS_LAMBDA = 0.35` and the star weights (30/20/25/10/15)
were unchanged since upstream's first commit (`d446f7a`), and the live
League numbers at defaults matched the pre-change capture. The owner then
set the intended default:

- `DEFAULT_CHAOS_LAMBDA` is now **0.75**. Star weights are unchanged.
- Hard-coded 0.35s now read the constant: the `sleeper.ts` fallback and
  initial draft score, the Astrolabe default, and the mock settings. The
  Settings drawer's λ fallback was 0.65 and now also reads the constant. The
  ChaosDial "Canonical" preset is now 0.75.
- The saved Oracle moved to a new key, `oneiromancy_oracle_v2`, and stores λ
  and weights only when the owner changes each one. The old version saved λ
  as a side effect of a weight change, which would have pinned 0.35 over the
  new default.
- Tests asserting the default (challenger m2 1.5 and tier5 adversarial; both
  outside the runner) now expect 0.75. The runner is unchanged: 142 passed,
  4 failed (the loader baseline). The tier5 adversarial file's 3 failures
  (7.1, 7.3, 7.6) occur without this change as well.
- Verified in the browser: a fresh session shows "λ 0.75 · mostly stars",
  League re-ranks accordingly, and a weight-only change stores only weights.
